# 裁剪弹窗双轨交互重设计 — 设计文档

**日期**: 2026-07-13
**状态**: 设计稿已定(Pencil `design/shots.pen` frame `TrimDialog-Redesign`),待写实现计划

## 问题

现有 `TrimDialog` 把裁剪和音频剪头两种语义**挤在同一个 84px 高的波形 canvas 上**,靠落点像素分裂:左 15% 拖 = 前段静音(只静音音频),其余拖 = 尾部裁剪(裁视频+音频)。没有光标变化、没有分界标记、静音手柄在值为 0 时不显示,下方还叠了一条冗余的蓝/灰裁剪 slider 把同一个值又画一遍却不体现音频。用户分不清"这是在裁视频还是动音频"。

## 目标

把交互拆成**两条带标签的横条轨**(视频轨 + 音频轨),用**一根贯穿两轨的裁剪线**把"裁剪同时影响视频和音频"这件事变成一眼可见的联动;把"前段静音"隔离成音频轨上独立的手柄。消除歧义,不改变后端 EDL 语义。

## 现状锚点(重设计基于这些既有事实)

| 项 | 现状 | 出处 |
|----|------|------|
| 裁剪语义 | 只裁**尾部**:保留 0..N 帧,同时截断视频和音频 | `effective_clip.py` `-vframes` + 音频 `atrim` |
| 前段静音语义 | 只把前 N 帧音频压 0(`volume` 滤镜),**不删帧、时间轴不动** | `effective_clip.py` head-mute 分支 |
| EDL 字段 | `trim_frames`、`audio_head_mute_frames` 两个正交字段 | `Shot` model |
| 保存 | 确认裁剪时按变化分别 `POST …/trim`、`PUT …/audio-head-mute` | `TrimDialog.handleTrim` |
| 只读标记 | 说话结束线(检测参考)、播放头(预览时) | `WaveformTrack` |
| 设计 token | Tailwind 同款(zinc/blue/amber/red/green),字体 Inter,radius 8 | `shots.pen` variables |

**本次不改后端语义**:仍是尾部裁剪 + 前段静音两个正交操作,两个既有端点不变。改的是前端交互与呈现层。

## 设计(以 Pencil 稿为准)

### 布局(弹窗内从上到下)

1. **标题栏**:`裁剪视频` + `Shot #N` 徽章 + 关闭
2. **视频预览器**(黑,16:9,保留现有播放器):左上角常驻提示「指针在视频轨上移动 → 预览器跳到该帧」
3. **双轨区**(核心,见下)
4. **图例**(两行):蓝=人声 · 灰=静音/已裁剪 · 红线=裁剪(视频+音频一起裁) · 蓝竖=前段静音(只静音音频) · 黄线=说话结束(参考) · 绿线=播放头(预览时)
5. **信息行**:`帧 N / N`,彩色 chip(`裁掉 N 帧`红、`前段静音 N 帧 · N.NNs`蓝),右侧 `时间 N.NNs / N.NNs`
6. **按钮行**:预览 · 步进 `-10 -1 +1 +10` · 取消 · 确认裁剪

### 双轨区的三条明确视觉规则

**① 视频轨(上)**:抽帧缩略图胶片条。裁掉的尾段用磨砂遮罩(`#F4F4F5CC`)变暗。

**② 音频轨(下)**:波形(蓝 `blue-500`=人声,灰 `zinc-300`=静音)。裁掉的尾段同样磨砂变暗。前段静音区域蓝色染(`#2563EB24`)。

**③ 手柄与线**:
- **裁剪线**:一根 `red-500` 竖线**贯穿视频轨 + 音频轨**,中部有红色抓手(pill + grip)。拖它 → 两轨尾部同时裁剪,视频预览器跟随 seek 到该帧。**这是"联动"的全部含义:一个动作、一根线、两轨同截。**
- **前段静音手柄**:`blue-600` 竖线,**只落在音频轨**,音频轨内独立蓝色抓手。拖它 → 只改前段静音区,不影响视频轨、不裁帧。
- **说话结束线**(`amber-500`)、**播放头**(`green-700`):只读,不可拖,只出现在音频轨(播放头预览时贯穿两轨)。

### 交互规格

| 操作 | 手势 | 效果 | 落库字段 |
|------|------|------|----------|
| 裁剪 | 拖裁剪线/红抓手(贯穿两轨) | 尾部裁剪点变化;视频预览 seek 到该帧;两轨尾段磨砂随动 | `trim_frames`（保存时 `POST …/trim`） |
| 前段静音 | 拖音频轨蓝抓手 | 前段静音帧数变化;仅音频轨蓝染随动 | `audio_head_mute_frames`（保存时 `PUT …/audio-head-mute`） |
| **hover 擦洗预览** | 指针在**视频轨**上移动/停住 | 视频预览器 seek 到指针所指帧;一条细游标线跟随指针(落在两轨上) | 无（纯预览，不落库） |
| 预览播放 | 预览按钮 | 播放头(绿)出现并沿两轨移动 | 无 |
| 步进 | `±1/±10` | 微调当前裁剪点 | 同裁剪 |

**消歧的本质**:裁剪线和前段静音手柄**分处不同轨、不同颜色、不同抓手**,不再靠"同一 canvas 上按像素猜落到哪个操作"。旧版那条冗余的蓝/灰 slider **删除**。

### 组件与样式

- 复用 `shots.pen` 设计系统:`component/Button`(确认裁剪)、色板变量、Inter 字体、radius 8。
- 轨高:视频轨 60px,音频轨 84px,轨间距 12px,左侧 44px 标签栏(视频/音频)。
- 颜色严格用既有 token,和现 `WaveformTrack` 一致(见现状表),避免视觉漂移。

## 范围与约束

- **仅前端交互/呈现层重构**;`trim`、`audio-head-mute` 两个端点及其字段语义不变。
- **裁剪仍只支持尾部**(后端不支持头部裁剪);头部只能"静音"不能"删帧"——这条约束在 UI 上通过"前段静音是音频轨独立手柄、不是裁剪线"来如实表达。
- 缩略图胶片条需要抽帧:优先复用已有帧资源(`last_frame`/poster/已生成帧),或后端新增轻量抽帧端点(实现计划再定,不在本 spec 拍死)。
- 弹窗内预览器需能体现前段静音/裁剪的音频效果(现状不能——现状弹窗内 `<video>` 播完整原音),是否接入 `useShotSync` 的静音逻辑留待实现计划评估。

## 待实现计划细化的开放项(非本 spec 拍死)

1. 缩略图抽帧来源:复用现有帧 vs 新增抽帧端点。
2. 弹窗内预览是否接入 head-mute/裁剪的音频静音(useShotSync 复用)。
3. 波形数据来源:沿用现有 `video-info` 波形接口。
4. 裁剪线的抓取热区宽度、hover 游标的节流。

## 验证要求(遵循 CLAUDE.md「音视频改动用解码内容验证」)

- 前端交互:e2e 驱动真实弹窗,拖裁剪线后断言真实 `GET /api/projects/{id}` 的 `trim_frames`/`trim_end_sec` 变化;拖前段静音手柄后断言 `audio_head_mute_frames` 变化——断言真实落库值,不断言注入值。
- 若触及任何影响音频内容的路径(如弹窗内预览接入静音),必须解码 PCM 做 RMS/时长内容比对,不能只看 `muted` 标志位。
